# system-one-code-review

- Before pushing, run `uv run ruff check`, `uv run ruff format --check`, `uv run mypy` and `uv run pytest`. CI runs the same and posts one sticky comment per pull request.
- Ruff fails a function with more than 9 decisions (mccabe complexity 10). Split the function; do not add `# noqa`.
- Every counted decision in `src/` and `scripts/` (an `if`, `elif`, `except` or `while`) carries a comment that reads as its condition in plain words: `if workers < 1:  # fewer than one worker was asked for`. Put it on the line above when the line would get long. The comment may name the outcome after `->`: `# a receipt already exists -> reuse it`.
- `uv run python -m scripts.decisions src/s1cr/github.py` renders a file's functions with their decisions; `--changed main` shows only what a branch changed. Packages and the PR comment follow the order `s1cr` reaches the functions, grouped by subcommand; one file lists top to bottom. A decision without a phrase shows 🟡.
- Every file `s1cr` keeps and every service it calls is named once in `src/s1cr/stores.py`, with a comment saying what it holds. Code reaches files and services through that module, never through a path or URL of its own.
- Data passed between functions is a dataclass or a TypedDict, each field with a comment saying what it holds. A signature takes and returns named data, never a bare `dict`, `list` or `tuple`, nor a dict of `Any`. Every function has a docstring whose first sentence says what it does.
- `uv run python -m scripts.flow` shows each command's steps, the data they pass, the files and services they touch and the rules they keep; `--changed main` shows what a branch changed in that. Whatever new or edited code leaves unnamed shows 🟡 there and in the PR comment; older code is fixed when it is next edited.
