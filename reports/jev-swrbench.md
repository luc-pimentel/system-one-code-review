# Jev on SWR-Bench

How well does TypeSafe's Jev, a System One model that answers with probabilities instead of writing text, review pull requests? Generated by `uv run s1cr score` from SWR-Bench (`ZZR0/SWRench@67ae1d4`) and 3 runs of `jev-1.13.0`, questions v1. The headline numbers are from run `r1`.

## Summary

| Question | Cases | Jev | Reference |
|---|---:|---|---|
| Would a reviewer ask for changes? | 983 (497 yes) | AUROC 0.57, accuracy 54% | chance 0.50; diff size 0.47; majority 51% |
| Does it introduce a functional defect? | 983 (276 yes) | AUROC 0.62, accuracy 72% | chance 0.50; diff size 0.49; majority 72% |
| Which kind of change? | 264 | accuracy 31% | always F.2 Logic 19%; random among 11 9% |
| Which file? | 277 | accuracy 75% | the file with the most changed lines 63%; a random file 50% |
| Asked again | 983 × 3 runs | yes/no answers flip for 1% and 1% | |
| Speed and cost | 983 calls | median 320 ms, $0.12 of input tokens | at TypeSafe's quoted $0.042 per million |

## What the numbers say

- **Whether a reviewer would ask for changes:** Jev ranks them above chance but not by much (AUROC 0.57), and its probabilities are worse than a constant: always answering 0.51 scores a Brier of 0.250 against Jev's 0.295. It gives pull requests reviewers asked to change a mean 0.71 and approved ones 0.67.
- **Whether it introduces a functional defect:** Jev ranks them above chance but not by much (AUROC 0.62); its probabilities are no better than a constant (Brier 0.203 against 0.202), and at 0.5 it is no more accurate than always answering no.
- **Which kind of change:** right 31% of the time, 1.7 times the best fixed answer (19%), and 62% of the time at least on functional against evolvability.
- **Which file:** right 75% of the time, against 63% for the best rule that reads no code; on its more confident half, 83%.
- **Acting on its own:** on neither yes/no question does trusting only Jev's surest answers keep errors at 10% or less for more than 6% of pull requests. On this data its yes/no answers are not reliable enough to approve or block a pull request alone.
- **Consistency:** asked again, its yes/no answers flip for 1% of pull requests or fewer, and its Choice answers agree 90% of the time or more.
- **Cost:** 983 pull requests for $0.12 of input tokens, median 320 ms each.

## 1. The data

SWR-Bench holds 1000 pull requests from 12 Python projects. 983 are scored (893 from 2011–23, 90 from 2024–25); 17 are left out:

- 10: a merge commit before the first review mixes other work into the diff
- 5: too large for one Jev call
- 2: over Jev's token limit

Jev sees each pull request as its first reviewer did: the title, the description (up to 6,000 characters) and the diff of every file, as of the last commit before the first review. It never sees the review, the later commits or the fixes. GitHub's own diff of a pull request shows its final state, fixes included, so for pull requests with several commits the reviewed diff comes from comparing the base commit with the last commit before the review.

The labels are what the reviewers asked for. A pull request counts as *changes requested* when a reviewer asked for at least one change the author then made; SWR-Bench's annotators sorted each request into functional (the code does not work) or evolvability (it works, but could be clearer or better built) categories.

## 6. Asking again

Every pull request went to Jev 3 times with the same input (983 answered every time). Jev's answers are not identical from one call to the next:

| Question | Mean change between two runs | 95% of spreads within | Answer at 0.5 flips |
|---|---:|---:|---:|
| Changes requested | 0.010 | 0.040 | 1% |
| Functional defect | 0.010 | 0.040 | 1% |

Choice questions picked the same top option in every run for 90% of the problem type answers and 96% of the fault file answers.

## 7. Speed and cost

Run `r1`: 983 calls, one per pull request with every question in it, answered by `jev-1.13.0` (983). Median call 320 ms, 90th percentile 381 ms, measured from this machine with 4 calls in flight. 2,855,141 input tokens (median 2043 per call) and 176,991 output tokens. At TypeSafe's quoted $0.042 per million input tokens that is $0.12; output tokens are not priced here.

## What this does not show

- **Reviewers miss things.** An approved pull request can still hold a bug nobody caught, and whether an evolvability change is worth asking for is partly taste.
- **The data is public.** These pull requests are on GitHub, so Jev may have seen them in training. The 2024–25 slice is the least exposed.
- **One wording.** Every question has one frozen wording (questions v1); other wordings would score differently.
- **Diff only.** Jev sees the diff, not the rest of the repository, which human reviewers could read.

## Reproduce

```sh
uv sync
uv run s1cr fetch                  # SWR-Bench at the pinned commit
uv run s1cr build                  # rows as Jev reads them; GitHub CLI login needed
TYPESAFE_API_KEY=... uv run s1cr run r1 --model jev-1.13.0
uv run s1cr score                  # rewrites this report
```
